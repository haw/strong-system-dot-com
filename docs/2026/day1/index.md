# Day 1: アプリケーションに権限を渡す（IAMロールとS3）

## 目標

EC2上のプログラムに、IAMロールを通じてS3を読む権限を渡します。ロールの許可を変えながら同じ要求を送り、結果の違いを確かめます。

- アクセスキーを入力せずに、EC2のロールでAWSへアクセスできることを確かめる。
- 許可がない状態、広すぎる許可の状態、必要な分だけ許可した状態を比べる。

ここで扱う考え方は、事前学習の4章（ポリシー）と5章（アプリケーションに権限を渡す）で説明しています。

## 構成

```text
あなたのブラウザー
  ├─ IAMコンソール：自分のロールを作成し、S3の許可を変更する
  └─ EC2コンソール：default VPCにEC2を作成し、Session Managerで接続する
                        ↓ EC2上でAWS CLIを実行
                  自分のEC2用IAMロール
                        ↓ 教材の読み取り
                  教材用S3バケット（講師が用意。全員で1つ）
                    ├─ trainees/{あなたの名前}/guide.txt（自分用の教材）
                    └─ comparison/guide.txt（全員共通の比較用教材）
```

教材用のS3バケットは講師が用意しています。教材の削除や上書きは、バケットポリシーで拒否されています。

## 重要: リソース名の命名規則

共有のAWSアカウントを使うため、**すべてのリソース名に `{あなたの名前}` を付けてください。** 自分の名前が付いたリソース以外は、変更・削除しないでください。

## 講師から配られる値

| 項目 | 例 |
| --- | --- |
| 自分のリージョン | `us-west-2` |
| 自分の名前（リソース名に付ける） | `tanaka` |
| 教材バケット名 | `day1-training-docs-xxxx` |
| 教材バケットのリージョン | `ap-northeast-1` |

手順の中の `{あなたの名前}`、`{教材バケット名}` などは、配られた値に置き換えてください。

---

## 手順1：IAMロールを作る

1. AWSマネジメントコンソールで **IAM** を開き、左メニューの「ロール」→「ロールを作成」を選ぶ。
2. 「信頼されたエンティティタイプ」で「AWSのサービス」、「ユースケース」で「EC2」を選び、「次へ」。
3. 許可ポリシーで `AmazonSSMManagedInstanceCore` を検索してチェックし、「次へ」。
4. ロール名に `day1-ec2-role-{あなたの名前}`（例：`day1-ec2-role-tanaka`）を入力し、「ロールを作成」。

このロールに付いているのは、Session Managerで接続するための権限だけです。S3の許可はまだありません。

作成したロールを開き、「信頼関係」タブを確認してください。次の内容は「EC2サービスがこのロールを使える」という意味です。

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Principal": { "Service": "ec2.amazonaws.com" },
      "Action": "sts:AssumeRole"
    }
  ]
}
```

## 手順2：EC2を作る

1. コンソール右上のリージョンを、配られた自分のリージョンに切り替える。
2. **EC2** を開き、「インスタンスを起動」を選ぶ。
3. 次のとおり設定する。書いていない項目は既定値のままでよい。

| 項目 | 設定 |
| --- | --- |
| 名前 | `day1-ec2-{あなたの名前}` |
| AMI | Amazon Linux 2023 |
| インスタンスタイプ | `t3.micro` |
| キーペア | 「キーペアなしで続行」。Session Managerで接続するので不要 |
| ネットワーク設定 | VPCはdefault VPCのまま。パブリックIPの自動割り当ては有効のまま |
| セキュリティグループ | ネットワーク設定の「編集」を選び、新規作成する。名前は `day1-ec2-sg-{あなたの名前}`。**SSHを許可するインバウンドルールは削除する**。インバウンドルールは不要 |
| 高度な詳細 →「IAMインスタンスプロファイル」 | 手順1の `day1-ec2-role-{あなたの名前}` |

4. 「インスタンスを起動」を選ぶ。
5. インスタンス一覧で、自分のEC2の「インスタンスの状態」が「実行中」になるまで待つ。

## 手順3：EC2へ接続し、誰の権限か確認する

1. 自分のEC2を選び、「接続」→「セッションマネージャー」→「接続」を選ぶ。起動直後で「接続」が押せない場合は、1〜2分待って画面を更新する。
2. 開いた **EC2上のターミナル** で実行する。CloudShellや手元のPCでは実行しない。

```bash
aws sts get-caller-identity --query Arn --output text
```

期待する結果：

```text
arn:aws:sts::{アカウントID}:assumed-role/day1-ec2-role-{あなたの名前}/{インスタンスID}
```

`assumed-role` と自分のロール名が含まれていれば、アクセスキーを入力せずにEC2のロールで動いています。

続けて、以降の手順で使う値を設定します。`{教材バケット名}`、`{あなたの名前}`、`{教材バケットのリージョン}` を配られた値に置き換えてください。認証情報ではなく、対象を指定するための値です。

```bash
BUCKET='{教材バケット名}'
NAME='{あなたの名前}'
export AWS_REGION='{教材バケットのリージョン}'
```

`AWS_REGION` には、EC2のリージョンではなく **教材バケットのリージョン** を指定します。違うリージョンを指定するとエラーになります。

## 手順4：①許可なしで読む

```bash
aws s3 cp "s3://$BUCKET/trainees/$NAME/guide.txt" -
```

**期待結果：拒否される**（`Forbidden` や `AccessDenied` と表示される）。ロールにS3の許可が1つもないため、何も書かれていなければ拒否されます（暗黙の拒否）。

## 手順5：②AmazonS3FullAccessで読む

1. IAMコンソールで自分のロールを開き、「許可」タブ →「許可を追加」→「ポリシーをアタッチ」を選ぶ。
2. `AmazonS3FullAccess` をチェックし、「許可を追加」。
3. EC2のターミナルに戻り、実行する。

```bash
aws s3 cp "s3://$BUCKET/trainees/$NAME/guide.txt" -
aws s3 cp "s3://$BUCKET/comparison/guide.txt" -
aws s3 ls
```

**期待結果：自分用も比較用も本文が表示される。`aws s3 ls` では、アカウント内のほかのバケットまで一覧に出る。** まだ拒否される場合は、30秒ほど待って再実行する。

次に、比較用教材の削除を試します。

```bash
aws s3 rm "s3://$BUCKET/comparison/guide.txt"
```

**期待結果：拒否される。** `AmazonS3FullAccess` は削除も許可していますが、教材用バケットのバケットポリシーが削除を明示的に拒否しているため、拒否が優先されます。

**考えること**：自分の教材を読むだけのプログラムに、この権限は必要でしょうか。

## 手順6：③自分の教材だけに絞る

1. 自分のロールの「許可」タブで `AmazonS3FullAccess` を選び、「削除」する。`AmazonSSMManagedInstanceCore` は削除しない。
2. 「許可を追加」→「インラインポリシーを作成」を選び、「JSON」に切り替えて次の内容に置き換える。`{教材バケット名}` と `{あなたの名前}` は配られた値に置き換える。

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "ReadMyGuide",
      "Effect": "Allow",
      "Action": "s3:GetObject",
      "Resource": "arn:aws:s3:::{教材バケット名}/trainees/{あなたの名前}/guide.txt"
    }
  ]
}
```

3. 「次へ」を選び、ポリシー名に `day1-read-my-guide` を入力して「ポリシーの作成」。
4. EC2のターミナルに戻り、実行する。EC2の再起動は不要です。

```bash
aws s3 cp "s3://$BUCKET/trainees/$NAME/guide.txt" -
aws s3 cp "s3://$BUCKET/comparison/guide.txt" -
aws s3 ls
```

**期待結果：自分用は本文が表示される。比較用と `aws s3 ls` は拒否される。** 比較用がまだ読める場合は、30秒ほど待って再実行する。

`aws s3 ls` が拒否されるのは想定どおりです。バケットの一覧表示の許可を付けていないためです。決まったファイルを読むだけなら、一覧表示の権限は必要ありません。

## 結果をまとめる

次の表を埋め、「何を変更したので結果が変わったか」を1文で書いてください。

| 段階 | ロールのS3の許可 | 自分の教材 | 比較用教材 | 比較用の削除 |
| --- | --- | --- | --- | --- |
| ① | なし | | （試さない） | （試さない） |
| ② | `AmazonS3FullAccess` | | | |
| ③ | 自分の教材1件の `GetObject` | | | （試さない） |

## 後片付け

講師の指示に従って行います。

1. Session Managerのセッションを終了する。
2. EC2コンソールで自分のEC2を選び、「インスタンスの状態」→「インスタンスを終了」。
3. インスタンスの状態が「終了済み」になったら、セキュリティグループ `day1-ec2-sg-{あなたの名前}` を削除する。
4. IAMコンソールで、ロール `day1-ec2-role-{あなたの名前}` を削除する。

## 詰まった場合

| 状況 | 確認すること |
| --- | --- |
| Session Managerで「接続」が押せない | 起動から数分待ったか。インスタンスの「セキュリティ」タブで、ロールが関連付いているか。パブリックIPがあるか |
| ARNに自分のロール名が出ない | CloudShellや手元のPCで実行していないか |
| リージョンに関するエラーが出る | `AWS_REGION` が教材バケットのリージョンになっているか |
| ②でも拒否される | 許可の反映を待ったか。ポリシーを付けたロールが、EC2に関連付いているロールと同じか |
| ③で自分の教材も拒否される | JSONのバケット名と名前、大文字小文字、`{` `}` の置き換え漏れ |
| ③で比較用がまだ読める | 許可の反映を待ったか。`AmazonS3FullAccess` を外し忘れていないか |
| ②で削除が成功してしまった | すぐに講師へ連絡する |
