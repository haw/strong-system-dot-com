# Day 3 記録の例

[Day 3 のハンズオン](./)の手順6で書く、障害の記録の例です。時刻は例です。自分のメモの時刻に置き換えて読んでください。

記録は、あとから読む人のために書きます。その場にいなかった人が読んでも、何が起きて、なぜそう言えて、何をしたのかが分かることを目指します。

## 全体

| 記録すること | 例 |
| --- | --- |
| 影響 | 社員名簿が、10時00分から10時35分まで使えなかった。画面は開くが、社員一覧が表示されず、登録もできなかった |
| 最初に見えたこと | 画面の「接続先」の下に `AccessDeniedException`。アプリケーションのログに `設定の読み込みに失敗しました` |
| 復旧の確認 | 「接続先」が水色の Amazon RDS になった。`E001`〜`E010` の一覧が表示され、`Z-tanaka` の登録と編集ができた |

## 障害ごと

外側から順に見えた順で書きます。1つ直すたびにエラーが変わったことも、記録に残しておくと、あとで経緯を追えます。

### 1. 設定を読めない

| 記録すること | 例 |
| --- | --- |
| 原因 | EC2 のロールのインラインポリシーで、`Deny` の `NotResource` が `/db` ではなく `/database` になっていた。自分のパラメータまで明示的に拒否されていた |
| 根拠 | エラーに `explicit deny` とあった。EC2 で `aws ssm get-parameters` を実行しても同じエラーになった。ポリシーの JSON で、`Allow` は `/db/*`、`Deny` の `NotResource` は `/database` だった |
| 復旧 | `NotResource` の2つのパスを `/db`、`/db/*` に戻した。`aws ssm get-parameters` で値が読めることを確かめ、アプリケーションを起動し直した。エラーが `ENOTFOUND` に変わった |

### 2. 名前を引けない

| 記録すること | 例 |
| --- | --- |
| 原因 | Parameter Store の `host` が、RDS のエンドポイントと1か所違っていた（`-db-` が `-bd-`） |
| 根拠 | ログの `host=` と、RDS のコンソールのエンドポイントが一致しなかった。`getent hosts` で、本当のエンドポイントは引けたが、ログの名前は引けなかった |
| 復旧 | `host` を、RDS のコンソールからコピーしたエンドポイントに戻し、アプリケーションを起動し直した。エラーが `ETIMEDOUT` に変わった |

### 3. 3306 に届かない

| 記録すること | 例 |
| --- | --- |
| 原因 | RDS のセキュリティグループから、アプリケーションのセキュリティグループを許可する 3306 のルールが消えていた |
| 根拠 | `/dev/tcp` で、5秒待たされてから `届かない` になった。RDS のセキュリティグループのインバウンドルールが空だった |
| 復旧 | タイプ「MYSQL/Aurora」、ソースがアプリケーションのセキュリティグループのルールを追加した。`/dev/tcp` で `届いた` を確かめ、アプリケーションを起動し直した。エラーが `Access denied for user` に変わった |

### 4. ログインできない

| 記録すること | 例 |
| --- | --- |
| 原因 | Parameter Store の `password` が、研修用パスワードと最後の1文字だけ違っていた（`x` が `X`） |
| 根拠 | `docker run ... mysql` では、研修用パスワードでログインできた。パラメータストアで値を表示すると、研修用パスワードと一致しなかった |
| 復旧 | `password` を研修用パスワードに戻し、アプリケーションを起動し直した。「接続先」が水色の Amazon RDS になった |

## 再発を防ぐには

1つ書ければ十分です。例をいくつか挙げます。どれも「気を付ける」ではなく、人が間違えても止まる、または、すぐに気付ける形です。

- **設定をコードで管理し、変更はレビューを通す。** ポリシー、セキュリティグループ、パラメータを CDK で管理し、コンソールで直接変えない。コードの変更は、別の人が確かめてから反映する。
- **コードと実際の設定のずれを見つける。** CloudFormation のドリフト検出を使うと、スタックの外で変えられた設定を見つけられる。
- **値は手で打たない。** エンドポイントは CDK が自動で入れる。パスワードは Secrets Manager で管理し、人が値を打たない。
- **利用者より先に気付く。** アプリケーションのエラーのログを数え、アラームで知らせる（Day 4）。今回は、利用者からの連絡で初めて気付いた。
