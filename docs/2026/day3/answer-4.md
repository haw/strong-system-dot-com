# Day 3 追加の障害の答え：セキュリティグループは正しいのに届かない

[Day 3 のハンズオン](./)の「余裕がある人へ」の答えです。

## 原因

自分の VPC のネットワークACLに、ルール番号 50 で「10.0.0.0/16 からの TCP 3306 を拒否」が足されています。ネットワークACLのルールは、番号の小さい順に評価され、最初に一致したルールが使われます。番号 100 の「すべて許可」より先に 50 の拒否が当たるので、セキュリティグループが正しくても止まります。

## 根拠

- 画面とログに `ETIMEDOUT` が出る。`/dev/tcp` で、5秒待たされてから `届かない` になる。
- RDS のセキュリティグループのインバウンドルールは正しい（タイプ「MYSQL/Aurora」、ソースが `day3-2026-app-sg-{あなたの名前}`）。
- ネットワークACLのインバウンドルールに、3306 を拒否するルール 50 がある。

## 直し方

1. **VPC** の「ネットワーク ACL」で、VPC が `day3-2026-vpc-{あなたの名前}` のネットワークACLを選ぶ。
2. 「インバウンドルール」タブ →「インバウンドルールを編集」を選ぶ。
3. ルール番号 50 の行を「削除」し、「変更を保存」を選ぶ。
4. `/dev/tcp` で `届いた` になることを確かめてから、4-0 のコマンドでアプリケーションを起動し直す。
