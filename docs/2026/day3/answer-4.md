# Day 3 障害4の答え：ログインできない

[Day 3 のハンズオン](./)の 4-4 の答えです。

## 原因

Parameter Store の `/day3-2026/{あなたの名前}/db/password` が、研修用パスワードと最後の1文字だけ違っています。小文字の `x` が、大文字の `X` になっています。

## 根拠

- `docker run ... mysql` では、研修用パスワードでログインできる。RDS は正常。
- パラメータストアで `password` の値を「表示」すると、研修用パスワード `Tr41n-Rds2026-Kq7mZx` と一致しない。

## 直し方

1. **Systems Manager** の「パラメータストア」で `/day3-2026/{あなたの名前}/db/password` を開き、「編集」を選ぶ。
2. 「値」を研修用パスワード `Tr41n-Rds2026-Kq7mZx` に置き換え、「変更を保存」を選ぶ。種類（SecureString）と KMS キーは変えない。
3. 4-0 のコマンドで、アプリケーションを起動し直す。

`Access denied for user` は DB のログインのエラーです。AWS の権限（IAM）のエラーではないので、IAM ロールを変えても直りません。障害1の `AccessDeniedException` とは、名前は似ていても別のものです。

## 現場では、こうして起きる

パスワードを入れ直す作業で、1文字を大文字と小文字で打ち間違えた。SecureString は画面で値が隠れているので、保存した後も気付きにくい誤りです。

## 直ったときの見え方

画面上部の「接続先」が水色の **Amazon RDS** になり、社員一覧が表示されます。手順5に進みます。
