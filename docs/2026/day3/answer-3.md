# Day 3 障害3の答え：3306 に届かない

[Day 3 のハンズオン](./)の 4-3 の答えです。

## 原因

RDS のセキュリティグループ `day3-2026-rds-sg-{あなたの名前}` から、アプリケーションのセキュリティグループ `day3-2026-app-sg-{あなたの名前}` からの 3306 を許可するルールが消されています。

## 根拠

- `/dev/tcp` で、5秒待たされてから `届かない` になる。
- RDS のセキュリティグループのインバウンドルールが空になっている。

## 直し方

1. **EC2** の「セキュリティグループ」で `day3-2026-rds-sg-{あなたの名前}` を選ぶ。
2. 「インバウンドルール」タブ →「インバウンドのルールを編集」→「ルールを追加」を選ぶ。
3. タイプ「MYSQL/Aurora」（ポート3306）、ソース「カスタム」で `day3-2026-app-sg-{あなたの名前}` を選び、「ルールを保存」を選ぶ。
4. `/dev/tcp` で `届いた` になることを確かめてから、4-0 のコマンドでアプリケーションを起動し直す。

ソースを `0.0.0.0/0` にしてはいけません。つながりはしますが、DB に誰でも接続を試せる状態になります。許可するのは、アプリケーションのセキュリティグループだけです。

## 現場では、こうして起きる

セキュリティグループの整理で、使われていないルールだと思い込んで消した。ソースが別のセキュリティグループのルールは、何のためのものか一目で分かりにくく、消されやすいルールです。

## 直ったときの見え方

待たされなくなります。代わりに、すぐに `Access denied for user` が出ます。障害4（4-4）に進みます。
